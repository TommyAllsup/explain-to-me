# Explain-to-Me 1.1.1 — Windows joins the tiny film crew

**Windows 11 x64 source release · 2026-10-17**

Version 1.1.1 adds native Windows setup and local agent workflows for narrated, captioned explainer videos. Use a reviewed manifest or select material from Markdown/plain text with template direction. Kokoro supplies local narration; the existing technical-whiteboard renderer produces 1280×720 video at 24 fps.

## Install the tagged release

With Node.js 24+ including npm and Git for Windows installed, run in PowerShell:

```powershell
git clone --branch v1.1.1 --depth 1 https://github.com/TommyAllsup/explain-to-me.git explain-to-me-v1.1.1
cd explain-to-me-v1.1.1
node scripts/setup.mjs
node scripts/explain.mjs --version
node scripts/explain.mjs build --manifest fixtures/golden-manifests/whisper-vs-tts.json --output out/first-movie
```

The version command prints `explain-to-me 1.1.1`. Setup prepares pinned JavaScript dependencies, the browser and Windows launcher, uv/Python 3.11, and the pinned Kokoro model/voices. FFmpeg/ffprobe come from Remotion. Global Python, pnpm, uv, and FFmpeg installs are unnecessary. Normal setup runs as an ordinary user with existing Windows runtime components; missing Visual C++/.NET components can require repair and administrator help.

For agent-assisted setup, paste the [Windows installer prompt](../install-windows-agent.txt) into an existing Codex or Claude Code session with local terminal access. [Examples](../quick-install.md#windows-111-with-codex-or-claude-code) cover both harnesses. Follow scoped command/path approvals when their permission policies require them.

## What changed

- Platform-aware narration and doctor checks: Windows selects Kokoro and rejects Apple speech with a clear explanation; macOS retains Apple speech and optional local models.
- Portable venv discovery, native dependency/phonemization checks, model checksums, and actual setup/doctor synthesis.
- A Windows browser launcher that preserves argument boundaries, proxy restrictions, standard I/O, exit status, and owned descendant cleanup.
- Windows agent jobs with process-tree ownership, private temp/cache/output directories, Unicode/space paths, and explicit reparse/device/network-path limits.
- Bundled-FFmpeg-compatible boundary sampling and actual full video/audio decoding, including a corruption regression that distinguishes decoding from stream copying.
- Windows/Linux static CI configuration and focused launcher, backend, file-boundary, and process cleanup tests.

Successful builds retain MP4, WAV, VTT, SRT, manifest, report, scene-boundary samples, and approved image copies. Unchanged warm builds reuse narration and rendered frames, with source/runtime/cache provenance in the report. Existing output targets are refused.

## Scope and limits

Native Windows local AI direction and ARM64 are deferred. Use `--director template` for documents or a prepared manifest. Template direction is extractive; it does not semantically summarize. The release adds no PDF/web input, music controls, cartoon flags, or Studio UI. The broader product roadmap remains separate from the package version.

Normal local builds and harness sandbox execution are different environments. A sandbox can deny media/browser execution or directory protection; request only the required approval or report the exact blocked command. Automated QC and sampled-frame inspection are separate from full human watch/listen approval. Whole-process network isolation remains unverified; renderer request auditing has its own evidence.

The existing `v0.2.0` tag and [release notes](0.2.0.md) retain their original macOS scope. No new macOS media run was performed on this Windows host. Project code is MIT; dependencies, voices, and models retain their separate terms. Read [third-party notices](../../THIRD_PARTY_NOTICES.md) and [security guidance](../../SECURITY.md).
